# Contributing

Start with [PRODUCT](PRODUCT.md), [ARCHITECTURE](ARCHITECTURE.md) and [ROADMAP](ROADMAP.md). Keep a change focused and describe the behaviour it fixes.

Run `npm run check` and the tests relevant to your change. Add invented fixtures rather than copying real messages or contacts. Include a package-version update when application behaviour changes.

Do not run live collection or maintenance against someone else's systems. Offline tests and `radar demo` need no credentials. Keep source evidence, proposed fit and human decisions separate in code and documentation.

The public repository currently demonstrates a concrete personal-use preset; broad product generalisation and a full new-install bootstrap are roadmap work.
